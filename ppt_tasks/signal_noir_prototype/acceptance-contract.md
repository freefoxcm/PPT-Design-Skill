# Acceptance Contract — Signal Noir Prototype

Rules:

- Do not rewrite a MUST requirement merely to fit an output.
- Every MUST requires visible evidence in the rendered pages.
- Record `PASS`, `NEEDS_REVISION`, or `BLOCKED` with evidence in `visual-review.md`.

## MUST

- [ ] 5 页全部使用 Signal Noir v1.0 主题 token。
- [ ] 封面不是左右二分结构。
- [ ] 五页使用五种不同构图，并分别体现穿透、放大、推进、聚焦、切换。
- [ ] 每页只有一个第一视觉焦点。
- [ ] 图表使用主题化信号线和高亮规则。
- [ ] 无重复卡片墙、默认 Excel 图表或随机装饰。
- [ ] 中文文字在演示尺度下可读。
- [ ] 标题、正文、图表、线条和图片均保持独立可编辑。
- [ ] PPTX、PDF、逐页 PNG 完成结构和视觉复核。

## SHOULD

- [ ] 页面形成建立、放大、推进、聚焦、切换的节奏。
- [ ] 图片与图表使用统一冷色和信号高亮处理。
- [ ] 关键数据点无需依赖图例即可理解。
- [ ] 页面标题均为结论句。

## NICE_TO_HAVE

- [ ] 章节转换使用淡入或轨迹延续动画。
- [ ] 主题支持浅色备用模式。
- [ ] 关键轨迹在多页中形成连续叙事。

## 证据规则

每条条件必须在 `visual-review.md` 中记录 PASS、NEEDS_REVISION 或 BLOCKED，并引用具体页码/区域；不能仅以脚本运行成功或文件存在作为完成依据。
